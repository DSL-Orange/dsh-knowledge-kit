# DSH 知识库 · 模式包（dsh-knowledge-kit）

> **一句话**：一套可复制的本地知识库骨架——**一个入口、四类记录、一个检查器、一道加工工序**。
> 文件只是载体；**能自己发现自己的问题**，才是它活着的标志。

---

## 这是什么 / 不是什么

| 是 | 不是 |
|---|---|
| **机制**（四类记录、水位、维护分流、两个主体两个日志） | 内容库——这里**没有**任何具体项目档案 |
| **结构**（分区、命名、链接铁律） | 数据库——纯 Markdown，任何编辑器可读 |
| **工具**（`records-check.mjs`，一台机器判据） | SaaS——没有服务端，没有账号 |
| **模板**（索引/约定/变更日志/想法簿/待优） | 一次性成品——它是个**骨架**，要你自己长 |

**为什么要"模式"而不是"内容"**：内容是本机的、会过期的、含隐私的；**模式是可迁移的**。

## 五步起步

```bash
# 1) 克隆
git clone <本仓库地址> my-kb
cd my-kb

# 2) 改 00-索引.md 顶部的"本库硬事实"（版本号、路径、余量）
# 3) 改 01-约定.md 里所有 <占位符>
# 4) 跑一次检查器（此时应为 0 error）
node _tools/records-check.mjs

# 5) 开始写：任何新知识 → 先建专题文件 → 回 00-索引.md 登记一行 → 变更日志记一笔
```

**顺序不能反**：入口 → 记录分类 → 检查器 → 分流 → 跑第一个周期。

## 目录结构

```text
.
├── 00-索引.md              唯一入口（路由表；人工维护）
├── 00-索引-台账.md          完整清单（由脚本生成，禁手改）
├── 01-约定.md              规矩：命名/链接/写范围/维护流程
├── 02-想法簿.md            只追加的碎碎念（还没到三次的东西）
├── 03-待优.md              只追加的"可以改的地方"（不是待办）
├── 10-概念/                理解层：它是什么、为什么这样
├── 20-操作/                动手层：怎么做、排障
├── 30-协作/                规矩层：记录机制、接手约定
├── 40-项目/                项目档案（每个子目录一个项目）
├── 50-管理/                管理本身：管理员专区
├── _信箱/
│   └── 维护/               大维护报备区（含格式模板）
└── _tools/
    └── records-check.mjs   四项检查：孤儿 / 断链 / NUL / 水位过期
```

**四种记录**（只按"能不能改"分）：

| 类 | 规则 | 回答什么 |
|---|---|---|
| **日志** | 只追加，永不改写 | 什么时候发生了什么 |
| **报告** | 阶段发布，不改写 | 这一阶段交付了什么 |
| **快照** | **必须覆盖**，顶部写**水位** | "**现在**是什么" |
| **索引** | 随时改 | 去哪查 |

> **关键判据**：**"某事实现在还成立吗"只由快照回答**，不由日志/报告回答。

## 七件核心机制

| # | 机制 | 一句话 | 详情 |
|---|---|---|---|
| 1 | **唯一入口 + 清单分离** | 路由表被读得最勤，清单越长越大，必须分开 | `00-索引.md` |
| 2 | **四类记录 + 水位** | 只有快照回答"现在是什么" | `30-协作/40-记录机制.md` |
| 3 | **命名 / 链接铁律** | 区内互链只用文件名；跨区一律走索引 | `01-约定.md` §1–§2 |
| 4 | **外部检查器** | 不靠人自觉，用退出码说话 | `_tools/records-check.mjs` |
| 5 | **维护分流** | 改完别人找路的能力不变＝小维护；会变＝大维护 | `01-约定.md` §11 |
| 6 | **两个主体两个日志** | 管理员作为"成员"写共同体日志，作为"管理者"写管理员日志 | `01-约定.md` §11.4 |
| 7 | **加工工序** | 档案 → 经验 → 知识；答不出"下次会做不同的事"就不是经验 | `01-约定.md` §11 |

## 每轮怎么跑

| 档 | 做什么 | 成功的证据 |
|---|---|---|
| **维护** | 清队列、消费报备、归档过长日志 | 检查器归零 |
| **规范** | 审"有没有按规范用"，改判据本身 | 审计表（重号/无编号/水位过期/错放区） |
| **加工** | 档案 → 经验 → 知识 | 提炼清单 + **出处回查** |

**收工三件事**：① 回入口登记一行 ② 日志记一笔 ③ **跑检查器，退出码 0**

**每周期一次"路测"**：备 10~12 道真题（含 3 道"库里没有"的负例），让**什么都不记得**的新会话只准看入口去找。
> 这是唯一能验证"入口好不好用"的办法——体积、字数、token 都测不出来。

---

## 三个最容易犯的错

1. **双入口 / 内容冗余** → 双维护 = 必然漏。**职能可以分，入口不能分。**
2. **无产物的步骤最容易漏** → 每一步写清"产物"；"读一下""核一下"这类没产物的步骤要显式列出来盯。
3. **自己评自己** → 越评越信。**必须有外部判据**（检查器 / 路测 / 出处回查）。
