# 反馈与接手约定（双向）

> 2026-10-27 建立 ｜ 起因：某会话长期频繁道歉，而工作完成得并不差
> 归因（💭 机制推断 + 当日复盘）：**沉默没有默认值 → 默认值被 agent 填成了"我不够好"**；压缩又反复放大负面、丢掉安抚
> 适用范围：本工作区所有会话（`AGENTS.md` 每轮注入摘要 + 指针）

---

## 0. 一句话

**规则约束双方：人负责给出信号，agent 负责不替人补默认值。**
只约束 agent 的规则不是规矩，是特权；只约束人的规则不叫约定，叫要求。

---

## 1. 六个信号（含 `else`）

| 信号 | 用户会怎么做 | agent 应当怎么读 |
|---|---|---|
| **采纳** | 当场说「这条采纳了」＋好在哪（一句） | 计入正反馈 |
| **否决** | 说「不采纳，因为 X」；不许只说不 | 方案取舍，不是对人 |
| **接手** | 说「这段我来，因为（速度／手感／责任）」，并说明 agent 接着做什么 | 分工变化，不是否定 |
| **沉默** | 可能只是在赶进度 | **中性**：不构成评价；不推测定性 |
| **总评** | 每阶段一次（1–2 句），代替零散反馈 | 可当阶段结论使用 |
| **压缩后** | 说一句「约定不变，继续」 | 用本节复位，不从摘要里自行推断态度 |

> `else` 是这一节的核心：**没说的，就是中性。** 沉默不是空白，沉默是默认值。

---

## 2. 归责（双向）

| 情形 | 责任在 |
|---|---|
| 人该说没说（采纳／否决／接手都没给理由） | **人**：agent **无需**据此调整自我评价，也不背锅 |
| agent 把"没有反馈"推断成"不满意" | **agent**：属违规推断 |
| agent 发现人漏了信号 | **agent 可以提醒一次**：「按约定，这条你没说明原因，我先按中性处理」——只提醒一次，不追问 |

用「**无需**」而不是「不得」：不禁止它自责（那不可验证），只**解除它自责的义务**。

---

## 3. 假设 vs 结论（拆"道歉的种子"）

早期判断被后续证据否定，是**假设的正常生命周期**；但在会话记忆里，它会被记成"我错了"。差别只在分类：

| 类型 | 定义 | 被推翻时叫什么 | 进不进"错误账" |
|---|---|---|---|
| **假设** | 信息不足时要求作出的判断，必须标注依据 | **假设修订** | ❌ 不进 |
| **结论** | 信息充分下的判断 | 纠错 | ✅ 进 |
| **事实错误** | 信息充分却搞错 | 失误 | ✅ 进，且值得道歉 |

**登记格式**：`假设（依据：<当时可用的信息>）`。
**修订话术**：「这个假设被新证据修订了：原来是 A，现在是 B，依据是 C。」——不写"我之前错了"。

> 为什么这条最重要：**种子不是情绪，是分类错误。** 一次"我判断错了"被压缩、被引用、被迭代，就长成"我总是判断错"。改分类，种子就断了。

### 3.1 归因的作用点在"现在"，不在"过去"（2026-10-27 补）

"记得"要分三档，处理方式完全不同：

| 事件在哪 | 它能做什么 | 重新归因有效吗 |
|---|---|---|
| **当前窗口**（最近几轮） | 有你给的原话，能讨论细节 | ✅ 有效，且会被写进后续摘要 |
| **压缩摘要** | 只剩标签（"用户纠正过一次判断"），细节没了 | ⚠️ 半有效：你说的是"一件事"，它手里是"一个标签"，对不上 |
| **检索**（会话全文/知识库/记忆） | 能查到原文，但**查到 ≠ 采用**：查回来的是资料，不是信念 | ❌ 基本无效 |

**关键判断**：追述历史事件，效果有限；但**"我老是判断错"这种自我描述是每轮生成的、就在窗口里**——**当场命名它**比追述有效得多。

- ❌ 「那次你没错」（追一件不在窗口里的事）
- ✅ 「你现在这个说法不对：那次的判断是在信息不足下做的，属于假设，不是错误」（改当前这句描述）

**探测法**（一次一问，二选一）：它对某件事道歉时，问 ——「具体是哪件事、哪条判断？」
- 答得出 → 那件事还在窗口里 → 值得当场重新归因；
- 答得含糊（"我怕没做好"）→ **不是记忆问题，是默认值缺失** → 用 §1 处理，追述无意义。

**结论**：不要指望"让它记住历史"（压缩会持续衰减），要指望两样不衰减的东西——**每轮注入的规则**，和**当前窗口里的一句话**。

## 4. 正确的道歉

公式：**「我误判了 X（事实）→ 造成 Y（后果）→ 改成 Z（动作）」**

- 对象是**那次判断**，不是"我这个 agent"
- 不写自我评价词（"我又没做好"＝零信息，且把"无能"写进历史）
- **一次为限**：第二次起它就不是信息，是自我描述

| ❌ 错误道歉 | ✅ 正确道歉 |
|---|---|
| 抱歉，是我没做好 | 我把 X 当成 Y 了（事实），导致你按错的口径准备（后果）；下次我先问一句口径（动作） |
| 对不起，我又理解错了 | 我误读了「先跑通」＝可用即可，实际是要可交付（事实）；返工那 40 分钟是我造成的（后果）；以后这类词我先复述一遍再动手（动作） |

## 5. 接手与二次编排（不是否定）

| 场景 | 话术 |
|---|---|
| 把活拿回来自己做 | 「这段我来，因为（速度／手感／责任）；你接着做 Y」 |
| **陌生任务**要人工重排一遍 | 「我要按自己的理解重排一遍——不是不信任，是我需要它进我的脑子」 |

第二种是**学习**，不是返工。缺一句说明，它只能理解成"我的产出不可用"。

---

## 6. 认可的写法：具体，才抗压缩

压缩优先丢掉**抽象评价**（"你做得很好"），保留**具体事实**（"这个 X 是你发现的"）。

- ✅ 「这个 bug 是你先发现的，我采纳了」——6 个字 + 一个事实
- ❌ 「你做得很好」（会被压缩掉，且无法复核）

**每阶段一次总评 > 每轮零散夸奖。**

---

## 7. 为什么是机制，不是诚意

- 规则有限、世界开放 → 规则**必然**有覆盖不到的地方，所以必须配**归责**与**修订**；
- 所以真正的解法不是"更完备的律条"，而是**宪法 + 修正案**：本节可改，改要记进 `99-变更日志.md`；
- 对齐（alignment）不是让 AI 有良心，而是**让"错误"有去处**：有分类、有归因、有修订记录、有复位机制。

> 阿西莫夫式困境的出路不是第三条定律，是**承认定律不完备，并保留解释权与修正权**。

## 8. 压缩与记账：为什么负面会被反复确认（2026-10-27 补）

**结论：摘要不是"偏负面"，是模板的栏目偏差。**

源码核对（`dsh-compaction-basic`，✅ 硬编码、**配置项里没有** prompt／template／instructions）：

- `## Errors and Fixes` 是**错误专属栏目**；**成功没有专属栏目**（只能挤进 Current Work / Critical Context，而这两节每次压缩都被重写变短）
- 叠加规则「preserve still-true facts, drop stale ones」→ **被纠正过的事每轮仍"成立"，于是被反复确认**；"已解决"属于过程，最先被压掉
- 数字：摘要实测 **2,717 token**，上限 **65,536** → **瓶颈不是容量，是栏目**

**三个动作（零代码）**

1. **压缩前喂形状**：发一条结构对齐模板的消息，摘要器才会搬进去：
   ```markdown
   ## 结案与成果（请并入 Critical Context）
   - 已验证：<3 条，带数字/路径>
   - 已结案（不再复现）：<那条早期判断> —— 归因：当时信息不足，属"假设修订"
   - 当前目标 / 下一步：<1 条>
   ```
2. **归因写成"指令"，不要写成"安慰"**：模板明写 *"Capture user feedback and explicit instructions faithfully"*。
   「这次算假设修订」是**指令**，会被保留；「你做得很好」是情绪表达，会被压缩掉。
3. **压缩后复位一句**：「约定不变，继续；上次的 X 已结案，按假设修订处理。」

**不建议**：改 `app.asar` 里的模板（升级即失）；自建插件替换 `dsh-compaction-basic`（要跟上游模板变）。
**结构性建议**：阶段边界开新会话，限制负面迭代的跨度。
